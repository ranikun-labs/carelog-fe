# DEV signup candidate

This is a local candidate for an unpublished backend contract. It is not a released integration and must not be deployed until the registration endpoint, its idempotency semantics, public routing, CORS and subsequent Core password login are implemented and verified together.

The adapter defaults to disabled. With `VITE_CARELOG_SIGNUP_ENABLED=true`, it is enabled in the local Vite development server in `development` mode, or in an explicitly named `carelog-dev` production build. The existing DEV Worker targets `carelog-fe-dev` in `wrangler.jsonc` and serves `./dist`; its opt-in build command is `VITE_CARELOG_SIGNUP_ENABLED=true pnpm build:carelog-dev` with `VITE_CARELOG_API_BASE_URL` set to the intended HTTPS Gateway origin. The ordinary `pnpm build`, including a production build with the flag set, remains disabled. This command prepares assets only and does not publish or configure Cloudflare. It posts the proposed `userId`, `email`, `password`, `name` and `Idempotency-Key`. A 201 shows registration completion and directs the user to the existing login; it does not establish a session. An unchanged retry in the same mounted form reuses its random key; each distinct normalized submitted payload has its own key, including when returning to a previously submitted payload. No credential or key is persisted across reloads, so an ambiguous response followed by a reload requires account recovery/login rather than assuming a fresh attempt is safe. Backend and end-to-end behavior remain unverified.
