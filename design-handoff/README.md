# Claude Design · Carelog 치료 경과 이어보기

Carelog는 고객의 맥락, 지난 접점, 후속 일정을 한곳에서 관리하는 서비스입니다. 이번 화면은 치료사가 다음 방문 전에 지난 증상, 시행 기록, 반응을 확인하고 원기록을 펼쳐보는 흐름입니다. Carelog 클릭 프로토타입 한 개를 만들어 주세요. Carelog FE `3222dca`의 `CustomerDetailPage`에 있는 다음 일정, 고객 메모, 방문 타임라인 순서와 기존 방문 상세 열기 흐름에서 출발합니다. 시각 기준은 `docs/design/carelog/README.md` 및 기존 제품 화면입니다. 첨부 `reference/`의 고객 상세 HTML은 클릭 흐름 참고 자료이며, UI 계약과 고객 상세·방문 타임라인 코드도 함께 제공합니다.

프로토타입 도구 막대에 **시나리오 선택 / 모바일 390px / 데스크톱 1440px / 초기화**를 둬 주세요. 실제 제품 화면 밖에 배치하고 **합성 데이터 시뮬레이션**이라고 표시합니다. 한 시나리오 안에서 더보기, 방문 상세, 돌아가기를 클릭할 수 있게 해 주세요. 폭 변경에서도 열린 방문과 목록 상태를 유지합니다. 늦은 결과 시나리오에서는 B 고객으로 이동한 뒤 도구 막대의 **A 고객 응답 지금 도착** 버튼으로 응답을 전달합니다.

| 방문 | 합성 증상 | 실제 시행 기록 | 반응 |
|---|---|---|---|
| 11월 20일 15:00 | 고개를 오른쪽으로 돌릴 때 불편하다고 말함 | 치료사가 목 움직임을 확인하고 가벼운 움직임 연습을 시행했다고 기록 | “목을 돌리기 편해졌어요.” 고객 진술. 지속 기간 미기록 |
| 11월 13일 14:00 | 오후에 목이 뻣뻣했다고 말함 | 목 움직임 확인을 기록 | 반응 미기록 |
| 11월 6일 09:30 | 증상 별도 기록 없음 | 앉은 자세에서 움직임 연습을 시행했다고 기록 | 고객이 연습 도중 새 불편은 없었다고 말함 |
| 10월 29일 16:00 (11월 22일에 뒤늦게 작성) | 장시간 책상 작업 후 목이 불편했다고 말함 | 시행 내용 미기록 | 반응 미기록 |
| 7월 10일 11:00 | 움직일 때 목 당김을 보고함 | 목 움직임 관찰을 기록 | 반응 미기록 |

각 행에 고유한 원기록 화면을 연결합니다. 별도의 **11월 24일 예정 방문**과 **11월 21일 취소 방문**도 고정 데이터에 넣습니다. 고객 A의 치료 경과에는 완료 방문 다섯 건만 실제 방문 시각 순서로 표시합니다. 고객 B에는 11월 18일 10:00 완료 방문 한 건을 넣습니다. 증상은 “오전 손목 사용이 불편했다고 말함”, 시행은 “손목 움직임을 관찰했다고 기록”, 반응은 “미확인”입니다. B 방문에는 별도 원기록을 연결합니다.

카드는 **증상 → 실제 시행 → 반응** 순서입니다. 라벨은 **고객 진술 / 치료사 시행·관찰 / 미확인**을 사용합니다. 기록된 사실과 고객의 직접 진술을 표시하고, 시안 문구에서 호전·효과·개선 여부나 진단·판단을 단정하지 않습니다. 다음 방문 질문은 누락된 기록을 확인하는 질문으로 표현합니다.

| 장면·상태 | 시작 | 행동 | 반응 → 끝 | 390px / 1440px |
|---|---|---|---|---|
| 첫 목록 정상 | 완료 방문 다섯 건 | 고객 상세 열기 | 최근 완료 방문 세 건 최신순. 예정·취소 방문은 경과에 표시되지 않음 | 모바일 한 열, 데스크톱 기존 상세 레이아웃에서 날짜와 핵심 내용이 읽힘 |
| 더보기 정상 | 세 건 표시 | 이전 방문 더보기 | 로딩 후 10월·7월 방문 순서로 추가. 보고 있던 위치 유지 | 두 폭에서 기존 목록을 유지하며 추가 로딩·마지막 항목 표시 확인 |
| 더보기 실패 | 세 건 표시 | 더보기 → 다시 시도 | 이미 읽던 목록과 위치를 유지. 실패 문구 후 재시도에서 두 건 추가 | 두 폭에서 오류 메시지와 재시도 행동 확인 |
| 원기록과 복귀 | 더보기 완료 또는 첫 방문 카드 | 원기록 보기 → 돌아가기 | 선택한 방문 원기록이 열림. 복귀 시 방문과 스크롤 위치, 가능하면 누른 버튼 포커스 복원 | 모바일 상세 이동과 데스크톱 기존 상세 표현에서 각각 복귀 |
| 빈 상태 / 첫 조회 실패 | 완료 방문 0건 또는 조회 실패 | 고객 상세 열기 → 실패 시 재시도 | 0건은 성공한 빈 상태. 실패는 다시 시도 가능한 별도 상태 | 두 폭에서 메시지와 다음 행동을 구별 |
| 기록 일부 누락 | 11월 20일 방문 | 반응과 확인 질문 보기 | 직후 반응은 고객 진술로 표시. 지속 기간은 미확인. “편해진 느낌은 얼마나 지속됐나요?”가 해당 누락에 연결됨 | 두 폭에서 진술, 미확인, 확인 질문의 위계 확인 |
| 늦은 결과 | A 고객 더보기 중 | B 고객으로 전환 → A 결과 도착 | B 상세에는 손목 기록 한 건만 표시되고 A의 목 관련 방문이 추가되지 않음 | 두 폭에서 고객 전환을 끝까지 실행 |

제품 UI 밖의 Product Owner용 **결정 필요** 패널에서 카드의 정보 밀도와 확인 질문을 **방문 카드 안 / 목록 끝**에 두는 후보를 비교할 수 있게 해 주세요. 기본 시안은 완료 방문 세 건과 더보기입니다. 미확인은 각 항목의 정상적인 표시 상태로 처리합니다.

인수 시 각 행을 두 폭에서 끝까지 클릭합니다. 키보드 이동과 상세 복귀 포커스, 긴 메모의 줄바꿈, 색상에 의존하지 않는 로딩·실패·미확인 표시를 확인합니다.
